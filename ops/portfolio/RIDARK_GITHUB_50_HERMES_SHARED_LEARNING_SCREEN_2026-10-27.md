## Promotion and teaching protocol

1. Source audit: canonical repo, tagged version, recent maintenance, license, model weights, third-party terms, telemetry, data residency, supply-chain vulnerabilities and current Windows compatibility.
2. Compare against the CURRENT installed baseline on the SAME approved fixtures and host. Record accepted quality, p95 latency, failure rate, critical errors, real tokens, peak RAM, resource cost and cost per successful task, including human review.
3. Promote only when clearly better for a business task with no compliance or security regression, or when required capability is missing and tests pass. **No numerical scores have been invented for untested repositories.**
4. Teach the rest via this existing shared RAD-01 document: concise concept, reference, design pattern, negative cases, synthetic exercise, evidence receipts, owner/reviewer. Merely updating a document does not retrain or live-synchronize running agents.
5. Keep Aider + Ollama, existing SQLite/FTS5, already researched Docling, Crawl4AI and Firecrawl, plus established approval workflow by default. Avoid additional standalone projects, schedules and duplicated trackers.
