# Hermes P0/P1 — Offline Local Staging Hardening V2 (2026-10-20)

**حالة الحزمة: `OFFLINE_REGRESSION_PASS` فقط. `G0/G-CODE/G1=NO-GO` و`PRODUCTION=HOLD`.**

## ما أُصلح بالفعل

كشف اختبار Git حقيقي، في مستودع **مؤقت فقط**، أن `local_stage.py` التاريخي يُحصي عملية `git mv` كصفّين في مخرجات `git status --porcelain -z`، مع أنها **ملف متتبع واحد تغيّر**. الفحص القديم: 2؛ الإصدار الجديد `local_stage_hardened_v2.py`: 1. تتعامل دالة `_tracked_porcelain_count` مع حقل المسار الأصلي الإضافي في حالات rename/copy، وترفض البيانات غير المتوقعة بدلاً من اعتماد عدّ مضلل.

## التحسينات الإضافية

- فحص مسارات الملفات، الدليل الهدف وآبائه لرفض symlink / junction بما فيها الروابط المكسورة قبل عمليات التجهيز. **هذه ليست حماية من TOCTOU أو طرف عدائي يغير المجلد أثناء العملية؛ استخدم فقط مجلدًا أبًا موثوقًا ومحليًا لا يكتب فيه طرف آخر.**
- رفض أسماء ZIP التي تحتوي محارف تحكم Windows وأسماء أجهزة إضافية (`CONIN$`, `COM¹` وغيرها) وأسماء مجلدات غير معيارية.
- وضع سقف 80 MiB لحجم ZIP قبل حساب بصمته، إضافة إلى حدود الملفات وفحص SHA256 السابق.
- إجراء Git status مع `GIT_OPTIONAL_LOCKS=0` و`--no-optional-locks` و`core.fsmonitor=false` بهدف الحد من تحديثات الفهرس والآثار الجانبية؛ لا يعني ذلك ضمان القراءة فقط في جميع حالات Git والإضافات الخارجية.
- الحفاظ على حالة `host_verified=false` والحظر الإنتاجي. لا تدمج هذه الأداة مع التثبيت الحي تلقائيًا.

## الاختبارات والأدلة

أُعيد تشغيل اختبارات P0/P1 السابقة البالغ عددها 110 بالإضافة إلى **30 اختبارًا جديدًا**: `Ran 140 tests ... OK` على Python 3.13.5 / Linux. تشمل الاختبارات الجديدة مستودع Git حقيقيًا ومؤقتًا، symlink غير صالح/مكسور، ZIP غير صالح أو متلاعب به، إعدادات أسماء Windows، وسلوك الفرز. لم يُختبر Windows الفعلي أو تكامل Docker/Hermes في هذه النسخة.

هذه الحزمة **إضافية**؛ تحفظ `local_stage.py` التاريخي للمقارنة ولإعادة تشغيل 110 اختبارًا، لكن **لا يُنصح باستخدامه لعمليات stage/host-snapshot الجديدة**. استخدم `local_stage_hardened_v2.py` من هذه النسخة الموثقة فقط. لم تُعدل الملفات المثبتة على الكمبيوتر ولا أرشيفات الإصدار القديم.

## طريقة اختبار مختبر مستقل

```sh
python -m unittest discover -s tests -p 'test_*.py' -v
```

## استخدام لاحق بعد مراجعة الأمن

```sh
python local_stage_hardened_v2.py host-snapshot --repo /PATH/TO/ISOLATED/REPO
python local_stage_hardened_v2.py stage --archive /PATH/TO/PINNED.zip --sha256 SHA256_FROM_INDEPENDENT_SOURCE --target /TRUSTED/NEW/TARGET
```

هذه **أمثلة** وليست أوامر على Windows المحلي. الهدف جديد تمامًا وأبوه يجب أن يكون موجودًا وموثوقًا. لا تستخدم ملف ZIP من مصدر مجهول، ولا تكتب في `C:\Users\m\AppData\Local\hermes` أو مستودع التطوير الجاري.

## حدود لم تتغير

لم يُثبت التشغيل الفعلي لـHermes باستخدام Docker؛ ESTOP يمنع NEW work لكنه لا يوقف تلقائيًا in-flight؛ `pending_messages` محجوب بالأذونات؛ النسخ المشفرة السابقة جزئية بالنسبة لتثبيت Hermes الكامل؛ الاستعادة الوظيفية الكاملة غير مختبرة؛ لا اختبار CI على هذا الفرع؛ لا اعتماد P0/P1 للإنتاج.

مرجع المهام الوحيد باقٍ: 45 work packages / 120 historical IDs / 16 streams في المصنف الأصلي؛ لا إنشاء سجلات حالات بديلة.
