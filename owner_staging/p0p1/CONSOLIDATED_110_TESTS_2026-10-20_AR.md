# Hermes P0/P1 — حزمة الاختبارات الموحدة (20 أكتوبر 2026)

هذا **تجميع إضافي مستقل** لأدوات سبق تطويرها، وليس تثبيتاً على Windows أو نسخة تشغيلية من Hermes. لا تغييرات في `main`، لا دمج، لا تحديث للتثبيت المحلي. Hermes المحلي هو المنفذ المستهدف مستقبلاً؛ هذه الأدوات للفحص والتحقق فقط.

## ما تم إثباته

- مطابقة بصمات SHA-256 الخارجية للأرشيفات الثلاثة المصدر قبل التجميع.
- اختبار سلامة الأرشيفات ومانيفست الأرشيف الخاص بـ ESTOP.
- **110/110** اختبارات Python standard library نجحت عند جمع المجموعات الأربع وتشغيلها مرة واحدة في بيئة مستقلة، دون بيانات أو حسابات حقيقية.
- اختبارات سلبية ضد خطأ discovery/import/runtime، مسارات ZIP غير الآمنة، الانحرافات البنيوية في المصدر، شروط Docker، وESTOP.
- أرشيف التجميع يحتوي على 9 ملفات Python (5 أدوات + 4 ملفات اختبارات)، وهذه الإيصالات والمانيفست.

## التشغيل الآمن على نسخة منفصلة

```sh
PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s tests -p 'test_*.py' -v
```

هذا الأمر يشغل كود Python، فلا تشغله إلا في مختبر منفصل موثوق، ولا تشغله على بيانات Hermes الإنتاجية. لا حاجة لتنفيذ أي أمر على جهاز المستخدم لإنجاز هذا التسليم.

## الحدود والأسباب التي تمنع الاعتماد

- لا اختبار تكامل فعلي على نسخة Hermes المحلية؛ HEAD المحلي المسجّل `7318e666c236aa8fffc3506c705d1c00a4821441` (ليس SHA السحابي المرجعي).
- ESTOP المصدر يمنع بدء عمل جديد؛ إلغاء in-flight وguard قبل كل dispatch غير مثبتين؛ واختبار ESTOP على Windows لم يُنفذ.
- Docker Engine 29.8.2 واختبار عزل حاوية مستقلة قد نجحا سابقاً، لكن عزل أداة Hermes غير مثبت.
- النسختان المشفرتان المثبتتان جزئيتان/مختلفتا النطاق؛ ملف pending_messages غير قابل للقراءة، والنسخة الكاملة native والاستعادة الوظيفية غير مثبتتين.
- branch CI لم يجر إثبات نجاحه؛ المتاح اختبارات محلية اصطناعية من الأرشيف. لا تدّعي هذه الحزمة تجاوز P0/P1.
